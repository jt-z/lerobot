修复原理见 [`02-损坏机理-物理行号等于index.md`](02-损坏机理-物理行号等于index.md)。
核心动作一句话：**丢掉 `file-009.parquet` 的最后一个 row group**。

## 前置判断

```bash
ROOT=/data/share/b601_20260910_164106
python - <<'EOF'
import json, glob, pyarrow.parquet as pq

want=json.load(open(root+'/meta/info.json'))['total_frames']
```

- 差为 **0** → 无需修复

## 安全修复流程

### 1. 确认备份

`data/chunk-000/file-009.parquet.bak` 应当是**原始损坏版**，sha256 为
`81518caf0f01893a98ac4cac2b49b054e3f7dc7d9526f1fe90c122211a3f0068`：

```bash
sha256sum $ROOT/data/chunk-000/file-009.parquet.bak
```

> ⚠️ 不要用 `file-009.parquet` 本身去覆盖 `.bak` 当作「备份」——
> 重传后两者内容相同，这样会丢掉唯一的原始参照，无法验证损坏是否变形。

### 2. 只读前 N−1 个 row group 重写

```python
import pyarrow as pa, pyarrow.parquet as pq, os

f = '/data/share/b601_20260910_164106/data/chunk-000/file-009.parquet'
src = pq.ParquetFile(f); md = src.metadata
rg = [md.row_group(i).num_rows for i in range(md.num_row_groups)]   # 末项应为 11005

# 关键：废弃块根本不进内存
tbl = pa.concat_tables([src.read_row_group(i) for i in range(md.num_row_groups - 1)])
if md.metadata:                       # 保住 ARROW:schema / huggingface 两个 key
    tbl = tbl.replace_schema_metadata(md.metadata)

tmp = f + '.repair_tmp'
pq.write_table(tbl, tmp, compression='snappy')   # 原文件各列均为 SNAPPY
```

### 3. 校验临时文件，通过后才原子替换

替换前必须逐项通过（任何一项不过就保留临时文件、人工介入）：

| 门槛 | 期望值 |

```python

```

| 坑 | 说明 |
