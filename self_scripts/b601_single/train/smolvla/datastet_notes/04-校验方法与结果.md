# 04-校验方法与结果

分两层：**结构层**（纯 pandas/pyarrow，秒级，不需要 GPU）和**解码层**（需 lerobot 环境，实拉帧）。

## 第一层：结构校验

对应 [`scripts/verify_dataset.py`](scripts/verify_dataset.py)（不带 `--decode`）。

### 四道门槛

| # | 检查 | 判据 | 为什么必须查 |
|---|---|---|---|
| 1 | 总行数 | 15 个 parquet 行数之和 **== meta `total_frames`** | 一行判定有没有废弃块；最灵敏 |
| 2 | 文件边界 | 每个文件 `物理起始行 == index 最小值`，`物理结束行 == index 最大值` | 定位是哪个文件开始错位 |
| 3 | 全局 `index` | 单调且唯一，恰为 `0..N−1` | 查漏帧、重复帧 |
| 4 | episode 语义 | `dataset_from_index` 处的行确为该集且 `frame_index==0`；`dataset_to_index−1` 处 `frame_index==length−1` | 直接验证取帧会不会串集 |

门槛 4 还要加两条结构断言：

- **episode 切换次数 == 集数 − 1**（每集只占一段连续区间，不交叉）
- 每集内 `frame_index` 从 0 单调递增

> 只比 `episode_index` 的**数量**是不够的——废弃块并不改变集数，
> 它改变的是**位置**。门槛 1、2 才是捕获它的关键。

### 实测结果（2026-09-18，修复后）

| 检查 | 结果 |
|---|---|
| 物理总行数 | 533,168 |
| meta `total_frames` | 533,168 ✅ |
| 文件边界全对齐 | 15/15 ✅（修复前 file-010..014 共 5 个错位） |
| `index` 单调唯一 `0..533,167` | ✅ |
| episode 边界语义错误 | **0** / 223 |
| episode 切换次数 | 222 == 223−1 ✅ |
| 每集 `frame_index` 从 0 递增 | ✅ |

### 接缝区专项（最高风险区）

修复的边界（418,359 → 418,360）两侧逐个 episode 单独验过，ep157–169 全部正确：

| episode | `ds[idx]` 返回的 `episode_index` | 位置 |
|---|---|---|
| ep160 | 160 | tail 在 `ds[418359]` |
| **ep161** | **161** | head 在 `ds[418360]`，tail `ds[420469]`（2,110 帧） |
| ep162 | 162 | head 在 `ds[420470]` |
| ep163 / 164 / 165 | 各自正确 | — |

修复前，`ds[420470]` 会取到 `file-009` 里那块标着 ep161 的废弃数据。

## 第二层：解码校验

对应 `scripts/verify_dataset.py --decode`。用 `LeRobotDataset` 真实取帧，
同时验证**数据侧定位**和**视频侧对齐**：

```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset
ds = LeRobotDataset('hellozjt/b601_20260910_164106', root=root)
f = ds[idx]
```

每个采样点断言：

| 断言 | 内容 |
|---|---|
| `episode_index` | 与 meta 中该 `index` 所属的 episode 一致 |
| `frame_index` | == `idx − dataset_from_index` |
| 三路图像 shape | 均为 `(3, 480, 640)` |
| 三路图像非全零 | `abs().mean() > 0`（防解码失败返回黑图） |

### 采样方案与结果

脚本默认 `--samples-per-ep 3`（每集**首 / 中 / 末**三帧，比只取首末更易捕获集内错位）：

| 采样 | 数量 | 失败 |
|---|---|---|
| 每集首 / 中 / 末 | 223 × 3 = **669** | **0** |
| 随机帧（`np.random.default_rng(0)`，可复现） | **400** | **0** |
| **合计** | **1,069** | **0** |

`ds.num_episodes=223`、`ds.num_frames=533,168`，与 meta 一致。

> 9-18 修复当时手工跑的那一轮用的是「每集首末两帧 + 400 随机帧」= **846 帧**（同样 0 失败）。
> 脚本落地后按默认三帧重跑，**1,069 帧同样 0 失败**——两个口径都记在这里，避免对不上。
> 9-16 首次修复的同类校验是「180 集边界帧 + 400 随机帧」，结论一致。

## 视频侧独立校验

解码校验之外，还单独核对了「视频时长 vs meta 时间戳」这一维度（不需要加载数据集）：

| 检查 | 结果 |
|---|---|
| 引用的 mp4 是否存在 | 80 个文件、**0 缺失** |
| 文件时长 ≥ meta `to_timestamp` | **0 截断** |

这条是判断**传输是否中断**的主要依据，见
[`01-数据集现状与传输状态.md`](01-数据集现状与传输状态.md)。

## 校验耗时与使用建议

| 层 | 耗时 | 建议时机 |
|---|---|---|
| 结构层（门槛 1） | 秒级 | **每次从源端同步后、开训前**必跑 |
| 结构层（全部门槛） | 秒级 | 同上，成本可忽略 |
| 解码层 | 分钟级（需加载 + 解码 846 帧） | 修完数据后、换数据集后、结果可疑时 |

> 门槛 1（总行数 == meta `total_frames`）是**性价比最高的一条**：
> 一行代码就能发现本文档描述的全部损坏，且不依赖 lerobot 环境。
