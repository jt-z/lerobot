# pi05 推理链路

目的：说清 `lx/` 下 π0.5（pi05）真机推理的调用链、每层职责，以及「3060 12GB 如何装下 4.14B 模型」的机制。
涉及文件：`lx/pi05_inference.sh`、`lx/tools/pi05_lite.py`；权重：`lx/output_pi05/007000/pretrained_model`。

## 一、运行链路

```
lx/pi05_inference.sh
  ├─ source self_scripts/b601_common/_env.sh            # 设备档案 + python 环境
  ├─ source .../b601_single/inference/lerobot/_common.sh # 默认值 + 检查 + 命令拼装
  ├─ 前置检查：模型文件 / config 自检 / CAN 复位 / 相机 / 校准 / 零位确认
  └─ b601_run_rollout
       └─ ENTRY_WRAPPER=lx/tools/pi05_lite.py
            ├─ 接管 PI05Policy.from_pretrained（构建期省显存 + strict 加载）
            ├─ 安装分段计时（embed_prefix / denoise_step / sample_actions）
            └─ lerobot.scripts.lerobot_rollout.main()
                 ├─ policy 预处理：normalizer → 状态分词 → tokenizer(96)
                 ├─ InferenceEngine：sync 或 rtc（后台线程换 chunk）
                 └─ robot.send_action（joint_directions 全 -1.0 + 重力补偿）
```

关键设计：**不改 lerobot 源码**。只在 `_common.sh:253-266` 加了 `ENTRY_WRAPPER` 分支，把入口换成 `python lx/tools/pi05_lite.py`，其余 robot / 相机 / 任务参数保持原样。

## 二、每层职责

| 层 | 文件 | 职责 | 关键位置 |
|---|---|---|---|
| 入口 | `lx/pi05_inference.sh` | 选 step / prompt / 后端；前置检查；拼 rollout 参数 | `:57-93` 默认值、`:99-116` 模型自检、`:122-141` CAN/相机/校准、`:186-192` 调 rollout |
| 环境 | `self_scripts/b601_common/_env.sh` | 按主机名载入 `devices/<host>.sh`、激活 python 环境、导出数据根 | `:17-28` 档案、`:50-73` 环境 |
| 公共层 | `.../inference/lerobot/_common.sh` | CAN/相机/校准检查、日志文件、`b601_run_rollout` 参数拼装 | `:250-302` rollout、`:220-222` 零位确认 |
| 显存/计时 | `lx/tools/pi05_lite.py` | 构建期 bf16、跳过 lm_head、strict 加载、逐 chunk 计时、离线 `--bench` | `:56-115`、`:168-218`、`:289-348` |
| 引擎 | `src/lerobot/rollout/inference/{sync,rtc}.py` | 每 tick 取动作；rtc 在后台线程预取并做 chunk 融合 | rtc 注入口 `rollout/context.py:339-341` |

## 三、12GB 能装下的原因（不是量化）

原始加载路径的问题：默认 fp32 构建 2.5B 主干（约 10GB）→ 建完才 `.to(bfloat16)`；再加两个 lm_head（790M / 1.58GB），12GB 卡在建模型阶段就 OOM。

|lite 包装器做的事|效果|位置|
|---|---|---|
|构建期把默认 dtype 切成 bf16|主干按训练精度直接建成 bf16|`pi05_lite.py:101-105`|
|两个 `lm_head` 建成 0 行后摘除|-1.58GB（推理路径不用）|`:78-86`、`:168-178`|
|action expert 词嵌入建成 0 行|构建期 -0.53GB（lerobot 建完就置 None）|`:87-95`|
|投影层恢复 fp32|避免和 fp32 的 noise/timestep 撞 dtype|`:118-128`|
|视觉塔（SigLIP+projector）转 bf16，并同步替换 `embed_image`|-0.82GB；原实现内部强制 fp32，只转参数会炸|`:134-165`|

逐项显存账（16.57GB → 6.97GB）与实测峰值见
[pi05 时延与显存分析 §二](../04_推理部署/pi05_分析_时延与显存.md#二显存)，本节只说明机制。

## 四、权重加载路径

`pi05_lite.py:191-218` 与原生 `from_pretrained` 的差别：

1. `safetensors.load_file`（mmap 零拷贝）+ `_fix_pytorch_state_dict_keys` + `_prepare_pretrained_state_dict`
2. 过滤掉已摘除的 `.lm_head.` key
3. `load_state_dict(strict=True)`，缺 key 直接抛错
4. **绝不静默退回随机权重**：原实现会 `except Exception` 吞掉加载失败，对机械臂极危险

私有 API 依赖（升级 lerobot 时要回归）：`_fix_pytorch_state_dict_keys`、`_prepare_pretrained_state_dict`。

⚠️ 加载期还有一个主机内存尖峰：`_fix_pytorch_state_dict_keys` 会把 paligemma 的 lm_head `clone()` 成 `embed_tokens`（`modeling_pi05.py:1114`），fp32 约 2.1GB 匿名内存；mmap 之外另算。

## 五、观测 → 动作数据流

| 项 | 值 / 说明 |
|---|---|
| 输入 | `observation.state` 7 维 + `observation.images.{hand,front,top}` 3×480×640 |
| 预处理 | rename(空) → to_batch → normalizer（状态/动作 QUANTILES，视觉 IDENTITY）→ **pi05 状态分词** → tokenizer（`max_length=96`，`padding_side=right`，`truncation=true`）→ device |
| 视觉 | `_preprocess_images` 转 float32、resize_with_pad 到 224×224、归一化到 [-1,1]（`modeling_pi05.py:1169-1245`） |
| 输出 | `action` 7 维 × `chunk_size=50`，`n_action_steps=50`（每 chunk 覆盖 50 tick @30Hz） |
| 去噪 | `num_inference_steps=10`（Euler 积分，pi05 是 flow matching） |

注意两处 token 长度不一致：`config.json` 里 `tokenizer_max_length=200`，但实际预处理器被改成 `max_length=96`。**真机走 96，离线 `--bench` 默认却读 config 的 200**，测速时必须显式 `--tokens 96`。

## 六、sync 与 rtc 在模型侧的差异

- `sync`：每个 chunk 结束阻塞推理一次，`select_action` 从模型拿到 50 步再逐步发。
- `rtc`：`rollout/context.py:339-341` 把 `--inference.rtc` 注入 `policy.config.rtc_config` 并调用 `init_rtc_processor()`；`predict_action_chunk` 额外接收 `inference_delay` 与 `prev_chunk_left_over`，在 `sample_actions → euler_integrate` 里做 chunk 融合（guided 模式）。

`RTC_QUEUE_THRESHOLD` / `RTC_EXECUTION_HORIZON` 的默认值见
[推理运行 §二](../04_推理部署/pi05_指南_运行与任务切换.md#二启动命令)，动作差异、丢步原因与选型见
[分析：sync 与 rtc 的选型与动作差异](../04_推理部署/pi05_分析_sync与rtc选型.md)。

## 七、验证与测速工具

| 工具 | 用途 | 用法 |
|---|---|---|
| `lx/tools/verify_actions.py` | 固定噪声 + 固定输入跑一次，对比不同加载路径/不同卡的动作 | `--lite 1 --tag 3060-lite` |
| `lx/tools/dump_consts.py` | 导出 buffer 与张量属性（`inv_freq`、`embed_scale`），定位构造期常量差异 | — |
| `pi05_lite.py --bench` | 随机图像/随机 token 离线测分段时延 | `--bench 007000 --chunks 12 --tokens 96` |

已核对结论（见 `lx/PI05_HANDOFF.md`）：

- 同卡 native vs lite：动作 max |Δ| = **0**
- 跨卡 3060 vs 4090：0.35% 量程
- 视觉塔 bf16 vs fp32：动作 max |Δ| = **0.249°**（门槛 1°）

## 八、必须保持的不变量

1. **prompt 逐字一致**：训练集 `meta/tasks.parquet`、推理脚本 `TASKS` 数组必须完全相同（已校验 4 条全 MATCH）。
2. **相机键名**：必须是 `front / hand / top`（脚本启动时会 assert）。
3. **方向修正**：`joint_directions` 全 `-1.0`，与采集一致；不一致则 state/action 不同坐标系。
4. **FPS=30**：训练数据 30Hz，改了时序会错位。
5. **state 7 维 / 三路相机**：少一路会被模型用全 -1 空图 + mask=0 静默补位（见风险清单）。
