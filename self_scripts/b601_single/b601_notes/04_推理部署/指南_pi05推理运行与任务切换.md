# pi05 推理运行与任务切换

目的：说明 pi05 真机推理怎么跑、4 条子任务 prompt 怎么切，以及它和 ACT 单任务脚本的区别。

## 一、运行前提

1. 从臂 `seeed_b601_rs_follower` 已校准（`~/.cache/huggingface/lerobot/calibration/robots/seeed_b601_rs_follower/follower.json`）
2. `can0` 未被其它进程占用（脚本会 `down → 1Mbps → up` 并清空残留帧）
3. 三路相机按 `devices/<host>.sh` 接好（kfzbox: hand=2609010 / front=2608006 / top=2610057）
4. **开跑前把从臂摆到零位（默认坐姿、夹爪闭合）**，脚本会等待 ENTER 确认
5. 权重目录存在：`lx/output_pi05/007000/pretrained_model`（`003000` 是截断文件，不可用）

## 二、启动命令

```bash
# 默认：007000 / rtc / 任务 0（长任务）
bash lx/pi05_inference.sh

# 换步数（目录名）
bash lx/pi05_inference.sh 007000

# 改同步推理（换 chunk 会阻塞控制环，仅排障）
INFERENCE_TYPE=sync bash lx/pi05_inference.sh

# 限定运行时长（秒）
DURATION=120 bash lx/pi05_inference.sh

# 不用 lite 包装器（显存足够的机器）
LITE_LOAD=0 bash lx/pi05_inference.sh

# 视觉塔回退 fp32
LITE_VISION_BF16=0 bash lx/pi05_inference.sh

# 加大 rtc 异步余量
RTC_QUEUE_THRESHOLD=40 RTC_EXECUTION_HORIZON=24 bash lx/pi05_inference.sh
```

默认参数总览（`lx/pi05_inference.sh:57-93`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `STEP` | `007000` | 权重子目录 |
| `POLICY_DTYPE` | `bfloat16` | checkpoint 本身就是 bf16 配置 |
| `NUM_INFERENCE_STEPS` | 10 | 与 config 一致 |
| `INFERENCE_TYPE` | `rtc` | `sync` 用于排障/需要 model 列动作追踪 |
| `RTC_QUEUE_THRESHOLD` | 35 | 剩余 35 步开始预取 |
| `RTC_EXECUTION_HORIZON` | 20 | 与上一段动作重叠 20 步 |
| `LITE_LOAD` / `LITE_TRACE` | 1 / 1 | 省显存 / 逐 chunk 打印时延 |
| `LITE_VISION_BF16` | 1 | 视觉塔 bf16 |
| `TASK_INDEX` | 0 | 4 条 prompt 的下标 |
| `FPS` / `DURATION` | 30 / 0 | 0 = 跑到 Ctrl+C |

## 三、4 条子任务 prompt（已与训练集逐字核对）

pi05 只有一个**混合任务权重**（`b601_mixed`：220 集 / 227,784 帧，4 条 prompt 一起训练），
**不按子任务拆权重**，切换任务只换 prompt。

| TASK_INDEX | prompt（`lx/pi05_inference.sh:76-81`） | 训练集 episode 数 |
|---|---|---|
| 0（默认） | Take a cup from the dispenser, put it on the white tray under the coffee spout, press the first lit button on the left with the gripper tip, then return to the home pose when it blinks | 110 |
| 1 | Pick up the coffee cup from the silver tray under the coffee machine spout and place it in cup placement area 1 | 40 |
| 2 | Pick up the coffee cup from the silver tray under the coffee machine spout and place it in cup placement area 2 | 40 |
| 3 | Pick up the coffee cup from the silver tray under the coffee machine spout and place it in cup placement area 3 | 30 |

训练集里的任务分布可直接查：

```bash
python3 -c "import pandas as pd; df=pd.read_parquet('b601_mixed/meta/episodes/chunk-000'); \
print(df['tasks'].explode().value_counts())"
```

### 例：放置杯子到区域 2

```bash
TASK_INDEX=2 bash lx/pi05_inference.sh
```

注意映射关系：`TASK_INDEX=1/2/3` 分别对应 **1/2/3 号取杯区**，不要把 2 记成“第 2 条 = 区域 1”。

### 临时改 prompt

```bash
TASK_DESCRIPTION="Pick up the coffee cup ... place it in cup placement area 2" \
  bash lx/pi05_inference.sh
```

脚本在校验前就保存了 `_B601_TASK_DESC_ENV`（`lx/pi05_inference.sh:50`），所以 `TASK_DESCRIPTION` 优先级高于 `TASK_INDEX`。
⚠️ 只建议用于调试；**不在 4 条训练 prompt 内的文本属于 OOD**，行为不可预期。

## 四、与 ACT 单任务脚本的区别

| | pi05（`lx/pi05_inference.sh`） | ACT（`run_act_place_area.sh`） |
|---|---|---|
| 权重 | 一个混合模型 `output_pi05/007000` | 每个区域一个模型 `act_place_area{1,2,3}_20261110/006000` |
| 切换区域 | `TASK_INDEX=1/2/3` | 命令行第一个参数 area |
| 后端 | 默认 rtc，可 sync | 仅 sync（ACT 不支持 RTC） |
| 入口 | `lx/pi05_inference.sh` | `self_scripts/b601_single/inference/lerobot/run_act_place_area.sh <1|2|3>` |
| 包装脚本 | 无（用 `TASK_INDEX`） | `run_act_area1.sh` / `run_act_area2.sh` / `run_act_area3.sh` |

ACT 的区域 2 命令：

```bash
bash self_scripts/b601_single/inference/lerobot/run_act_area2.sh
# 等价于
bash self_scripts/b601_single/inference/lerobot/run_act_place_area.sh 2
```

两者 prompt 文本相同（同一份 `tasks.parquet`），但权重、后端、脚本完全不同，不要混用。

## 五、启动时会做哪些检查

| 检查 | 行为 | 位置 |
|---|---|---|
| `lerobot-rollout` 可用 | 不可用则尝试激活 conda 环境，仍失败退出 | `_common.sh:89-108` |
| 模型文件齐全 | 缺文件退出 | `pi05_inference.sh:99-103` |
| config 自检 | 必须 `type=pi05`、相机键正好 `front/hand/top` | `:106-116` |
| CAN 复位 | `down → 1Mbps → up`，`candump` 清空残留帧 | `:122-137` |
| CAN 状态 | 不存在退出，未 UP 则尝试拉起 | `_common.sh:147-160` |
| 相机设备 | **只告警不退出**（风险点，见问题清单） | `_common.sh:163-173` |
| 校准文件 | 缺失退出并提示先校准 | `_common.sh:176-186` |
| 零位确认 | 等待 ENTER | `_common.sh:220-222` |

## 六、常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `control ack timeout: comm_type=4` | CAN 队列/电机侧残留半截指令 | 重跑脚本（会复位 can0）；仍失败则给从臂断电重上电 |
| `RX=0` / 从臂不应答 | 从臂未上电或 `can0` 被占用 | 检查供电、`ip -details link show can0` |
| 动作明显不对 / 乱动 | prompt 不在训练集、方向修正不一致、state 与训练不同分布 | 确认 `TASK_INDEX`、`joint_directions` 全 `-1.0` |
| 模型加载报缺 key | 权重不完整（如 `003000` 截断） | 换 `007000`，核对文件大小 16GB |
| `GLIBCXX_3.4.26 not found` | IDE 注入了自带 libstdc++ | 脚本已清理 `LD_LIBRARY_PATH`（`:41-44`） |

## 七、日志与统计

- 日志：`self_scripts/_logs/inference_b601_pi05_b601_<STEP>_<时间戳>.log`
- 逐 chunk 时延：搜索 `chunk#`
- rtc 实际延迟：搜索 `real_delay=`

```bash
# chunk 时延分位
grep -oP 'chunk#\d+ total=\K\d+' self_scripts/_logs/inference_b601_pi05_*.log \
  | sort -n | awk '{a[NR]=$1} END{print "n="NR, "p50="a[int(NR/2)], "p95="a[int(NR*0.95)]}'

# rtc 队列最低余量
grep -oP 'real_delay=\K\d+' self_scripts/_logs/inference_b601_pi05_*.log | sort -n | head -1
```
