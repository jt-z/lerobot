## 四、b601_mixed 怎么来的

- 仓库里**没有**合并脚本，也没有合并日志。
- 它是 `b601_1` + `b601_2` 的简单叠加（110+110=220 集，143,480+84,304=227,784 帧，4 条 task 全保留）。
- 需要重做时用仓库自带工具：

```bash
# 方式一：命令行（lerobot 0.6.x 自带）
lerobot-edit-dataset --root /path/to/b601_mixed --operation.type merge

# 方式二：代码
python -c "from lerobot.datasets.aggregate import aggregate_datasets; ..."
```

（实现见 `src/lerobot/scripts/lerobot_edit_dataset.py` 与 `src/lerobot/datasets/aggregate.py`。）

## 五、公共参数层（改这里，别改入口脚本）

采集脚本都先 source `b601_common/_env.sh`，参数按「设备档案 → 默认值」两层取值：

| 文件 | 作用 | 关键内容 |
|---|---|---|
| `b601_common/_env.sh` | 总入口：按 `hostname` 选档案、激活环境、导出 `B601_DATA_ROOT` | `:16-28` 设备档案、`:32-38` 默认值、`:40-46` 主臂串口、`:49-73` python 环境、`:75` 数据根 |
| `b601_common/devices/_defaults.sh` | 通用默认值 | `:24` `joint_directions` 全 `-1.0`；`:33-36` 相机 640×480/30fps/MJPG；`:39` 角色 `hand front top`；`:68` `b601_cameras_json()` |
| `b601_common/devices/kfzbox.sh` | 当前机器（kfzbox） | `:11` 数据根 `~/b601_data`；`:14` 主臂 `/dev/rebot_leader`；`:30-33` 相机 2609010 / 2608006 / 2610057 |
| `b601_common/devices/z790.sh` | 另一台采集机（z790） | `:11` 数据根 `~/LX/pai0/b601_data`；`:14` 主臂 `/dev/ttyUSB0` |

⚠️ **方向修正 `joint_directions` 必须全 `-1.0`**，两边不一致会让 state/action 落在不同坐标系，训练出来的策略推理时方向全反。覆盖方式：在 `devices/<host>.sh` 里改，不要改入口脚本。

## 七、注意事项

1. **prompt 三处必须一致**：采集脚本里的 `TASK_DESCRIPTION`、数据集 `meta/tasks.parquet`、推理时的 prompt。改了文本等于换了任务，必须重采。
2. **一次 record 只能一条 prompt**：多 prompt 数据集只能像 05 那样多次启动 + `--resume` 续写。
3. **CAN 复位**：脚本启动时会 `down → 1Mbps → up` 并清空残留帧，避免 `control ack timeout: comm_type=4`。手动跑前不要占用 `can0`。
4. **数据根不统一**：02 落 `~/b601_data`，05/06 落仓库根，合并训练前先确认路径。
5. **`tee` + Ctrl+C**：脚本已 `trap '' PIPE`，不要手改成 `set -e` 直接跑 record，否则中断时可能跳过断开清理（电机保持使能）。
6. **日志是最好的溯源依据**：`self_scripts/_logs/` 里每个 record 日志的 `argv` 段落完整记录了当时的 repo_id、root、相机、prompt。
