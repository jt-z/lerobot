# SmolVLA 推理流程总览

## 一、整体架构概览

推理脚本 `run_inference_smolvla.sh` 是整个推理的入口，通过 `lerobot-record` 命令启动。

整个推理流程可以分为以下几个核心阶段：

```
命令行参数 → 配置解析 → 模型加载 → 预处理 → 推理 → 后处理 → 机器人执行
```

### 入口脚本

位置: `self_scripts/run_inference_smolvla.sh`

核心命令:
```bash
lerobot-record \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.cameras="..." \
  --dataset.single_task="Put ball to the cup" \
  --dataset.episode_time_s=200 \
  --policy.path=$POLICY_PATH \
  --policy.device=cuda \
  --policy.empty_cameras=1
```

## 二、推理循环主流程

位置: `src/lerobot/scripts/lerobot_record.py` 的 `record_loop()` 函数

每帧执行以下步骤（30fps，约 33ms 一帧）：

```
1. robot.get_observation()       # 获取机器人观测（图像+状态）
2. robot_observation_processor   # 观测预处理
3. predict_action()              # 核心推理
4. robot.send_action()           # 发送动作给机器人
5. dataset.add_frame()           # 保存数据（可选）
```

### 核心推理函数：predict_action

位置: `src/lerobot/utils/control_utils.py`

```python
def predict_action(observation, policy, device, preprocessor, postprocessor, use_amp, task, robot_type):
    with torch.inference_mode(), torch.autocast(...):
        # 1. 准备观测（转 tensor + batch 维度 + 放入 task）
        observation = prepare_observation_for_inference(observation, device, task, robot_type)
        # 2. 预处理流水线
        observation = preprocessor(observation)
        # 3. 模型推理
        action = policy.select_action(observation)
        # 4. 后处理
        action = postprocessor(action)
    return action
```

**关键点**:
- 使用 `torch.inference_mode()` 禁用梯度计算
- 支持 AMP（自动混合精度）加速
- 输入输出都经过 processor pipeline

## 三、预处理流水线

位置: `src/lerobot/policies/smolvla/processor_smolvla.py`

### 预处理步骤（输入侧）

1. **RenameObservationsProcessorStep** - 重命名观测特征
   - 对应脚本中的 `--dataset.rename_map` 参数
   - 例如把 `front` → `camera1`, `side` → `camera2`

2. **AddBatchDimensionProcessorStep** - 添加 batch 维度
   - 从单样本扩展为 batch=1

3. **SmolVLANewLineProcessor** - 确保 task 以换行符结尾
   - PaliGemma/SmolVLM 架构的要求

4. **TokenizerProcessorStep** - 语言 token 化
   - 把 task 文本转换为 token IDs + attention mask
   - 使用 SmolVLM2 的 tokenizer
   - max_length = 48

5. **DeviceProcessorStep** - 数据移到 GPU
   - 对应 `--policy.device=cuda`

6. **NormalizerProcessorStep** - 归一化
   - 图像: IDENTITY（不做归一化，在模型内部处理）
   - 状态: MEAN_STD（用数据集统计量归一化）

### 后处理步骤（输出侧）

1. **UnnormalizerProcessorStep** - 反归一化动作
   - 把归一化的动作值还原为真实的关节角度

2. **DeviceProcessorStep** - 移回 CPU
   - 准备发送给机器人

## 四、一次完整推理的时间线

由于 Action Chunking 机制，实际每 50 帧才调用一次完整的模型推理：

```
每帧 (30fps → ~33ms):
├── 机器人采集图像 + 状态 (~10ms)
├── 预处理（resize, tokenize, normalize）(~2ms)
├── select_action()
│   ├── 如果动作队列空 → 调用模型推理（大约每 1.67s 一次）
│   │   ├── embed_prefix (图像编码 + 语言嵌入)
│   │   ├── 前缀 KV cache 计算
│   │   └── 10 步 Flow Matching 去噪
│   │       └── 每步: embed_suffix + transformer forward + action_proj
│   └── 从队列取一个动作（其余帧直接取）
├── 后处理（反归一化）
└── 发送给机器人
```
