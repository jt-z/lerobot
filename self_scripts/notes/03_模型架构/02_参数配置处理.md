# 参数配置处理详解

## 一、参数传递路径总览

```
命令行参数 (--policy.xxx, --dataset.xxx, --robot.xxx)
        ↓
draccus 解析框架
        ↓
RecordConfig (lerobot_record.py)
        ↓
PreTrainedConfig.from_pretrained()
        ↓  (合并: checkpoint 配置 + CLI 覆盖)
SmolVLAConfig
        ↓
make_policy() → 模型实例化
```

---

## 二、命令行参数解析机制

### 解析框架：draccus

位置: `src/lerobot/configs/parser.py`

LeRobot 使用 `draccus` 库进行命令行参数解析，支持嵌套的 dataclass 配置。

### 特殊处理：policy.path

位置: `src/lerobot/scripts/lerobot_record.py` 的 `RecordConfig.__post_init__`

```python
def __post_init__(self):
    # 提取 --policy.path 的值
    policy_path = parser.get_path_arg("policy")
    
    if policy_path:
        # 提取所有 --policy.xxx 的覆盖参数（除了 path 和 type）
        cli_overrides = parser.get_cli_overrides("policy")
        
        # 从 checkpoint 加载配置，并用 CLI 参数覆盖
        self.policy = PreTrainedConfig.from_pretrained(policy_path, cli_overrides=cli_overrides)
        self.policy.pretrained_path = policy_path
```

**关键机制**：
- `--policy.path` 是特殊参数，触发从 checkpoint 加载配置
- 其他 `--policy.xxx` 参数作为 `cli_overrides` 覆盖 checkpoint 中的默认值
- 最终配置 = checkpoint 保存的配置 + CLI 覆盖参数

## 三、配置类层次结构

### 继承关系

```
draccus.ChoiceRegistry + HubMixin + ABC
        ↓
PreTrainedConfig (基类，所有 policy 共用)
        ↓
SmolVLAConfig (SmolVLA 特定配置)
```

### 基类 PreTrainedConfig

位置: `src/lerobot/configs/policies.py`

**核心字段**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `n_obs_steps` | int | 观测步数（历史帧数量） |
| `input_features` | dict | 输入特征定义 |
| `output_features` | dict | 输出特征定义 |
| `device` | str | 设备 (cuda/cpu/mps) |
| `use_amp` | bool | 是否使用自动混合精度 |
| `use_peft` | bool | 是否使用 PEFT 微调 |
| `pretrained_path` | Path | 预训练模型路径 |

**自动处理**:
- 如果 `device` 不可用，自动切换到可用设备
- 如果 AMP 不可用，自动关闭

### SmolVLA 特定配置

位置: `src/lerobot/policies/smolvla/configuration_smolvla.py`

**输入输出结构**:

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `n_obs_steps` | 1 | 观测步数 |
| `chunk_size` | 50 | 每次推理输出的动作序列长度 |
| `n_action_steps` | 50 | 每次推理实际执行的步数 |
| `max_state_dim` | 32 | 状态向量最大维度（不足则 padding） |
| `max_action_dim` | 32 | 动作向量最大维度（不足则 padding） |

**图像预处理**:

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `resize_imgs_with_padding` | (512,512) | 图像 resize 尺寸（保持宽高比） |
| `empty_cameras` | 0 | 空相机数量（用全黑图像填充） |

**语言处理**:

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `tokenizer_max_length` | 48 | 语言 token 最大长度 |
| `pad_language_to` | "longest" | padding 策略 |
| `vlm_model_name` | "HuggingFaceTB/SmolVLM2-500M-Video-Instruct" | VLM 模型名称 |

**Flow Matching**:

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `num_steps` | 10 | 去噪步数 |
| `use_cache` | True | 是否使用 KV cache |

**模型架构**:

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `attention_mode` | "cross_attn" | 注意力模式 |
| `num_vlm_layers` | 16 | VLM 使用的层数 |
| `num_expert_layers` | -1 | Action Expert 层数（-1 表示和 VLM 相同） |
| `self_attn_every_n_layers` | 2 | 每隔几层加自注意力 |
| `expert_width_multiplier` | 0.75 | Expert 宽度倍数 |

### empty_cameras 的作用

位置: `configuration_smolvla.py` 的 `validate_features()`

```python
def validate_features(self) -> None:
    for i in range(self.empty_cameras):
        key = f"{OBS_IMAGES}.empty_camera_{i}"
        empty_camera = PolicyFeature(
            type=FeatureType.VISUAL,
            shape=(3, 480, 640),
        )
        self.input_features[key] = empty_camera
```

`empty_cameras` 会在 `input_features` 中添加虚拟的相机特征，确保模型输入形状与预训练时一致。

## 四、from_pretrained 加载流程

位置: `src/lerobot/configs/policies.py` 的 `PreTrainedConfig.from_pretrained()`

### 步骤

1. 找到配置文件路径
   - 本地目录: 直接找 `config.json`
   - Hub 仓库: 用 `hf_hub_download` 下载

2. 读取 JSON 配置文件

3. 根据 `type` 字段确定具体的配置类（如 "smolvla" → SmolVLAConfig）

4. 用配置数据实例化配置类

5. 应用 CLI 覆盖参数（`cli_overrides`）

## 六、模型加载流程

位置: `src/lerobot/policies/factory.py` 的 `make_policy()`

### 完整步骤

```python
def make_policy(cfg, ds_meta=None, env_cfg=None, rename_map=None):
    # 1. 获取 policy 类
    policy_cls = get_policy_class(cfg.type)  # "smolvla" → SmolVLAPolicy
    
    # 2. 从 dataset 或 env 推断特征形状
    features = dataset_to_policy_features(ds_meta.features)
    cfg.output_features = {key: ft for key, ft in features.items() if ft.type is FeatureType.ACTION}
    cfg.input_features = {key: ft for key, ft in features.items() if key not in cfg.output_features}
    
    # 3. 加载预训练模型
    if cfg.pretrained_path and not cfg.use_peft:
        policy = policy_cls.from_pretrained(
            pretrained_name_or_path=cfg.pretrained_path,
            config=cfg,
        )
    
    # 4. 放置到设备
    policy.to(cfg.device)
    
    return policy
```

### PEFT 支持

如果 `use_peft=True`：
1. 先加载 PEFT adapter 配置
2. 从 adapter 配置中找到 base model 路径
3. 加载 base model
4. 再加载 PEFT adapter
