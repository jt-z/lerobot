# 文字描述（Task）处理流程详解

## 一、传递路径总览

```
脚本参数 --dataset.single_task="Put ball to the cup"
        ↓
lerobot_record.py 中 record_loop() 作为 single_task 参数
        ↓
predict_action(..., task=single_task, ...)
        ↓
prepare_observation_for_inference() → observation["task"]
        ↓
preprocessor 流水线中的 SmolVLANewLineProcessor
        ↓
preprocessor 流水线中的 TokenizerProcessorStep
        ↓
OBS_LANGUAGE_TOKENS (token IDs) + OBS_LANGUAGE_ATTENTION_MASK
        ↓
模型 embed_prefix() 中的语言嵌入层
        ↓
与图像嵌入、状态嵌入拼接后送入 Transformer
```

## 二、各阶段详细说明

### 阶段 1：脚本参数传入

脚本: `self_scripts/run_inference_smolvla.sh`

```bash
--dataset.single_task="Put ball to the cup" \
```

这个参数会被解析到 `RecordConfig.dataset.single_task` 字段。

### 阶段 2：进入推理循环

位置: `src/lerobot/scripts/lerobot_record.py` 的 `record_loop()`

```python
action_values = predict_action(
    observation=observation_frame,
    policy=policy,
    device=get_safe_torch_device(policy.config.device),
    preprocessor=preprocessor,
    postprocessor=postprocessor,
    use_amp=policy.config.use_amp,
    task=single_task,           # ← 任务描述从这里传入
    robot_type=robot.robot_type,
)
```

### 阶段 3：放入 observation 字典

位置: `src/lerobot/policies/utils.py` 的 `prepare_observation_for_inference()`

```python
def prepare_observation_for_inference(observation, device, task=None, robot_type=None):
    # ... 图像和状态的转换 ...
    
    observation["task"] = task if task else ""
    observation["robot_type"] = robot_type if robot_type else ""
    
    return observation
```

此时 `task` 还是**纯文本字符串**，和图像、状态数据放在同一个 observation 字典里。

### 阶段 4：SmolVLANewLineProcessor - 换行符处理

位置: `src/lerobot/policies/smolvla/processor_smolvla.py`

```python
@ProcessorStepRegistry.register(name="smolvla_new_line_processor")
class SmolVLANewLineProcessor(ComplementaryDataProcessorStep):
    def complementary_data(self, complementary_data):
        if "task" not in complementary_data:
            return complementary_data
        
        task = complementary_data["task"]
        new_complementary_data = dict(complementary_data)
        
        if isinstance(task, str):
            # 确保以换行结尾
            if not task.endswith("\n"):
                new_complementary_data["task"] = f"{task}\n"
        
        return new_complementary_data
```

**为什么要加换行符？**
SmolVLA 使用的是 SmolVLM2（PaliGemma 架构），这种 VLM 的 tokenizer 期望 prompt 以 `\n` 结尾，这是预训练时的格式约定。

### 阶段 5：TokenizerProcessorStep - 文本分词

位置: `src/lerobot/processor/tokenizer_processor.py`

这是最关键的一步，把文本转换为模型可以处理的 token IDs。

#### 配置参数

来自 `SmolVLAConfig`：

| 参数 | 值 | 说明 |
|------|-----|------|
| `tokenizer_name` | `"HuggingFaceTB/SmolVLM2-500M-Video-Instruct"` | 使用 SmolVLM2 的 tokenizer |
| `max_length` | `48` | 最大 token 数 |
| `padding` | `"longest"` | padding 策略（按 batch 内最长序列） |
| `padding_side` | `"right"` | 右侧 padding |
| `truncation` | `True` | 超长则截断 |

在 `processor_smolvla.py` 中的配置：
```python
TokenizerProcessorStep(
    tokenizer_name=config.vlm_model_name,
    padding=config.pad_language_to,      # "longest"
    padding_side="right",
    max_length=config.tokenizer_max_length,  # 48
)
```

#### 处理过程

```python
def observation(self, observation):
    # 1. 从 complementary_data 中取出 task
    task = self.get_task(self.transition)
    
    # 2. 调用 tokenizer 分词
    tokenized_prompt = self._tokenize_text(task)
    # 返回: {"input_ids": tensor, "attention_mask": tensor}
    
    # 3. 移动到正确的设备
    target_device = self._detect_device(self.transition)
    
    # 4. 添加到 observation 字典
    new_observation = dict(observation)
    new_observation[OBS_LANGUAGE_TOKENS] = tokenized_prompt["input_ids"]
    new_observation[OBS_LANGUAGE_ATTENTION_MASK] = tokenized_prompt["attention_mask"].bool()
    
    return new_observation
```

#### tokenizer 调用

```python
def _tokenize_text(self, text):
    return self.input_tokenizer(
        text,
        max_length=self.max_length,      # 48
        truncation=self.truncation,      # True
        padding=self.padding,            # "longest"
        padding_side=self.padding_side,  # "right"
        return_tensors="pt",             # 返回 PyTorch tensor
    )
```

**经过这一步后**：
- `observation.images.camera1` → 图像 tensor（形状不变）
- `observation.state` → 状态 tensor（形状不变）
- **新增** `observation.language_tokens` → token IDs，形状 `(batch_size, 48)`
- **新增** `observation.language_attention_mask` → bool 掩码，形状 `(batch_size, 48)`

### 阶段 6：嵌入层编码 - 从 token 到向量

位置: `src/lerobot/policies/smolvla/modeling_smolvla.py` 的 `embed_prefix()`

```python
lang_emb = self.vlm_with_expert.embed_language_tokens(lang_tokens)

# Normalize language embeddings
lang_emb_dim = lang_emb.shape[-1]
lang_emb = lang_emb * math.sqrt(lang_emb_dim)
```

调用的底层实现（`smolvlm_with_expert.py`）：
```python
def embed_language_tokens(self, tokens: torch.Tensor):
    return self.get_vlm_model().text_model.get_input_embeddings()(tokens)
```

这一步将离散的 token ID（整数）映射为连续的词向量：
- **输入**: `(batch_size, 48)` 的整数 tensor
- **输出**: `(batch_size, 48, hidden_size)` 的浮点 tensor
  - hidden_size 取决于模型大小，500M 模型约为 512 或 1024

**为什么要乘以 `sqrt(dim)`？**
这是 Transformer 中的常见技巧，用于缩放嵌入向量的范数，使得它和位置编码的量级匹配，有助于训练稳定性。

### 阶段 7：与其他模态拼接

位置: `src/lerobot/policies/smolvla/modeling_smolvla.py` 的 `embed_prefix()`

```python
embs = torch.cat(embs, dim=1)           # 拼接所有嵌入
pad_masks = torch.cat(pad_masks, dim=1)  # 拼接所有掩码
att_masks = torch.tensor(att_masks, ...) # 注意力类型标记
```

最终的前缀序列结构：

```
[图像嵌入] + [语言嵌入] + [状态嵌入]
   ↓            ↓           ↓
  N_img        48          1
 tokens     tokens      token
```

其中语言 token 的数量取决于文本长度，最多 48 个（超过会被截断）。

## 三、关于 48 个 token 的限制

### 确认配置

在 `configuration_smolvla.py` 中：
```python
tokenizer_max_length: int = 48
```

在 `tokenizer_processor.py` 中：
```python
truncation: bool = True  # 超过 max_length 会被截断
```

### 行为说明

- 如果文本 token 数 **≤ 48**：右侧 padding 到 48
- 如果文本 token 数 **> 48**：截断到前 48 个 token（后面的内容丢掉）

### 48 个 token 大概是多少文本？

SmolVLM2 使用的是 **Gemma tokenizer**（SentencePiece 子词分词器），大致换算：

| 语言 | 大致字符数 | 大致单词/汉字数 |
|------|-----------|----------------|
| 英文 | ~200-300 字符 | ~30-40 个单词 |
| 中文 | ~80-150 字符 | ~40-60 个汉字 |

### 示例

**短文本**（正常情况）:
```
文本: "Put ball to the cup"
Token: [Put, ▁ball, ▁to, ▁the, ▁cup, <eos>, <pad>, <pad>, ..., <pad>]
       ↑ 约 6 个有效 token，其余 42 个是 padding
```

**接近上限**:
```
文本: "Pick up the red block from the left side of the table and place it carefully inside the green box"
Token: 约 30-40 个 token，接近上限
```

**超长文本**（会被截断）:
```
文本: 很长一段话（超过 48 个 token）
结果: 前 48 个 token 保留，后面的直接丢弃
```

### 为什么限制在 48？

1. **任务描述通常很短** - 机器人操作任务的语言指令一般都很简洁
2. **计算效率** - 前缀序列越短，KV cache 越小，推理越快
3. **预训练数据** - SmolVLA 预训练时使用的任务描述也大致是这个长度范围

**结论**: 48 对于机器人任务来说通常**绰绰有余**，因为机器人指令不需要长篇大论。

## 四、注意力掩码的设计

在 `embed_prefix` 中，`att_masks` 用来控制不同模态之间的注意力。

### 注意力掩码类型

| 模态 | att_mask 值 | 含义 |
|------|------------|------|
| 图像 tokens | 0 | 前缀部分，可互相关注 |
| 语言 tokens | 0 | 前缀部分，可互相关注 |
| 状态 token | 1 | 因果注意力的分界点 |

### 2D 注意力掩码生成

通过 `make_att_2d_masks()` 函数生成：

```
图像 token  可以关注 → 图像 + 语言 token
语言 token  可以关注 → 图像 + 语言 token
状态 token  可以关注 → 图像 + 语言 + 之前的状态/动作
动作 token  可以关注 → 图像 + 语言 + 状态 + 之前的动作
```

### 设计原因

- 图像和语言是"条件输入"，应该互相融合理解
- 状态和动作是"生成目标"的一部分，需要因果注意力来保证生成顺序
- 图像/语言不能"预见"未来的状态和动作

## 五、完整示例：从文本到模型输入

以 `"Put ball to the cup"` 为例：

| 步骤 | 数据形式 | 形状/大小 |
|------|---------|----------|
| 1. 原始文本 | 字符串 `"Put ball to the cup\n"` | - |
| 2. Tokenize | token IDs (整数序列) | `(1, 48)` 含 padding |
| 3. 嵌入层 | 词向量 | `(1, 48, hidden_size)` |
| 4. 缩放 | 乘以 `√dim` | 同上 |
| 5. 拼接 | 与图像+状态拼接 | `(1, total_tokens, hidden_size)` |
| 6. Transformer | 自注意力处理 | 同上 |
