## 2️⃣ 硬件规格对比

### SO-100 vs SO-101

虽然代码相同，但硬件上有细微差异：

| 特性 | SO-100 | SO-101 |
|------|--------|--------|
| **关节数量** | 6 (shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper) | 6 (相同) |
| **电机型号** | Feetech STS3215 | Feetech STS3215 |
| **通信协议** | 串口（Feetech协议） | 串口（Feetech协议） |
| **控制寄存器** | 相同 | 相同 |
| **软件接口** | 完全相同 | 完全相同 |
| **硬件差异** | 可能在机械结构、负载能力等方面略有不同 | - |

### 关键点

1. **软件层面**：完全相同的驱动代码
2. **标定独立**：每个机械臂都需要独立标定，无论是SO-100还是SO-101
3. **配置通用**：使用相同的配置参数和控制逻辑

## 3️⃣ 双臂支持情况

### BiSOFollower支持两种型号

**文件位置**：`src/lerobot/robots/bi_so_follower/bi_so_follower.py`

```python
class BiSOFollower(Robot):
    """
    [Bimanual SO Follower Arms](https://github.com/TheRobotStudio/SO-ARM100) 
    designed by TheRobotStudio
    """
    
    def __init__(self, config: BiSOFollowerConfig):
        # 创建两个SOFollower实例
        self.left_arm = SOFollower(left_arm_config)
        self.right_arm = SOFollower(right_arm_config)
```

### 支持的组合

由于SO-100和SO-101使用相同的代码，`BiSOFollower`支持以下组合：

| 组合 | 支持状态 | 说明 |
|------|---------|------|
| **SO-100 + SO-100** | ✅ | 两个SO-100作为双臂 |
| **SO-101 + SO-101** | ✅ | 两个SO-101作为双臂 |
| **SO-100 + SO-101** | ✅ | 混合使用（不推荐，但技术上可行） |

#### SO-100

#### SO-101

config = SO101FollowerConfig(

## 5️⃣ 注册机制

### 配置注册

**文件位置**：`src/lerobot/robots/so_follower/config_so_follower.py:46-47`

```python
@RobotConfig.register_subclass("so101_follower")
@RobotConfig.register_subclass("so100_follower")
@dataclass
class SOFollowerRobotConfig(RobotConfig, SOFollowerConfig):
    pass
```

这意味着：
- `type="so100_follower"` → 使用 `SOFollowerRobotConfig`
- `type="so101_follower"` → 使用 `SOFollowerRobotConfig`（同一个类）

def make_robot_from_config(config: RobotConfig) -> Robot:

## 7️⃣ 常见问题

### Q1: SO-100和SO-101可以互换吗？

**答**：在软件层面可以，但需要注意：
- ✅ 代码完全相同
- ✅ 配置参数相同
- ⚠️ **标定文件独立**：每个机械臂都需要单独标定
- ⚠️ 硬件规格可能略有差异（负载、精度等）

### Q2: 如何知道我的机械臂是SO-100还是SO-101？

**答**：
1. 查看硬件标识或购买记录
2. 在软件配置中，两者可以互换使用
3. 关键是使用正确的标定文件，而不是型号名称

### Q3: 双臂系统可以混用SO-100和SO-101吗？

**答**：技术上可以，因为：
- 代码接口相同
- 通信协议相同
- 每个臂独立标定

但**不推荐**混用，因为：
- 可能存在性能差异
- 增加维护复杂度
- 影响双臂协调性

### Q4: 为什么代码中要区分SO-100和SO-101？

**答**：主要是为了：
1. **清晰的配置**：用户可以明确指定使用的硬件型号
2. **未来扩展**：如果将来需要针对不同型号添加特定功能
3. **文档和示例**：帮助用户识别硬件类型
4. **语义清晰**：让代码更易读

但在当前实现中，这两者在代码层面是**完全相同**的。

## 8️⃣ 实际使用建议

### 推荐做法

1. **明确标注您的硬件型号**
   - 在配置文件中使用正确的`type`（`so100_follower`或`so101_follower`）
   - 在文档中记录实际硬件型号

2. **使用独立的标定文件**
   - 每个机械臂单独标定
   - 使用描述性的标定文件名（如`jt_left_so101.json`）

3. **双臂系统使用相同型号**
   - 避免混用不同型号
   - 确保两个臂的性能一致

### 数据集兼容性

由于SO-100和SO-101使用相同的代码：
- ✅ 数据格式完全相同
- ✅ 动作空间相同（12维双臂）
- ✅ 策略模型可以互换使用
- ⚠️ 但标定参数可能不同，不能直接复制策略权重到不同标定的机械臂

## 9️⃣ 总结

### 核心结论

1. **SO-100和SO-101在LeRobot中使用完全相同的代码**
   - `SO100Follower = SOFollower`（类型别名）
   - `SO101Follower = SOFollower`（类型别名）

2. **BiSOFollower同时支持两种型号**
   - 通过通用的`SOFollower`基类实现
   - 支持任意组合（理论上）

3. **唯一的区别是配置标识**
   - `type="so100_follower"` vs `type="so101_follower"`
   - 用于工厂方法路由和文档清晰度

4. **实际差异在硬件和标定**
   - 每个机械臂需要独立标定
   - 硬件规格可能略有不同
   - 软件接口完全统一
