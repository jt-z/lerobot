## 🔢 舵机原始值的含义

### Feetech STS3215 舵机编码器

**原始位置编码范围**：`0 - 4095` (12位编码器)

| 原始值 | 物理含义 |
|--------|---------|
| 0 | 舵机物理最小位置（约 -180°）|
| 2048 | 舵机中心位置（0°）|
| 4095 | 舵机物理最大位置（约 +180°）|

**转换公式**：
```
物理角度 = (原始值 - 2048) / 4096 * 360°
```

**示例**：
- 原始值 2048 → 0°
- 原始值 3072 → (3072 - 2048) / 4096 * 360° ≈ 90°
- 原始值 1024 → (1024 - 2048) / 4096 * 360° ≈ -90°

## 🎯 归一化范围 [-100, 100]

### 为什么是 [-100, 100] 而不是 [-1, 1]？

你的配置中：
```python
'use_degrees': False  # 使用归一化范围
```

但实际上 LeRobot 使用的归一化范围是 **[-100, 100]**，而不是 [-1, 1]。

### 归一化公式

```python
normalized_value = ((current_pos - range_min) / (range_max - range_min)) * 200 - 100
```

**反推原始值**：
```python
current_pos = (normalized_value + 100) / 200 * (range_max - range_min) + range_min
```

## 📐 详细计算示例

### 示例1：elbow_flex (肘关节弯曲)

**校准数据**：
- `range_min = 942`
- `range_max = 3159`
- 运动范围 = 3159 - 942 = **2217 步**

**警告日志**：
```python
'elbow_flex': {
    'original goal_pos': 99.63,   # 归一化值
    'safe goal_pos': 99.12        # 裁剪后
}
```

#### 计算 original goal_pos 的物理位置

```python
# 归一化值 99.63 → 原始值
original_pos = (99.63 + 100) / 200 * (3159 - 942) + 942
             = 199.63 / 200 * 2217 + 942
             = 0.99815 * 2217 + 942
             = 2212.9 + 942
             = 3154.9 步

# 对应的物理角度
angle = (3154.9 - 2048) / 4096 * 360°
      ≈ 97.3°
```

**含义**：Leader 要求 Follower 移动到接近**最大运动范围**的位置（99.63% 接近上限）。

#### 计算 safe goal_pos 的物理位置

```python
# 归一化值 99.12 → 原始值
safe_pos = (99.12 + 100) / 200 * (3159 - 942) + 942
         = 199.12 / 200 * 2217 + 942
         = 2206.3 + 942
         = 3148.3 步

# 差异
difference = 3154.9 - 3148.3 = 6.6 步
```

**被裁剪掉的距离**：只有 **6.6 步**，约占运动范围的 0.3%。

### 示例3：wrist_flex (腕部弯曲)

**校准数据**：
- `range_min = 879`
- `range_max = 3082`
- 运动范围 = 3082 - 879 = **2203 步**

**警告日志**：
```python
'wrist_flex': {
    'original goal_pos': 60.17,
    'safe goal_pos': 55.99
}
```

#### 计算物理位置

```python
# original goal_pos: 60.17 → 原始值
original_pos = (60.17 + 100) / 200 * (3082 - 879) + 879
             = 160.17 / 200 * 2203 + 879
             = 0.80085 * 2203 + 879
             = 1764.3 + 879
             = 2643.3 步

# safe goal_pos: 55.99 → 原始值
safe_pos = (55.99 + 100) / 200 * (3082 - 879) + 879
         = 155.99 / 200 * 2203 + 879
         = 0.77995 * 2203 + 879
         = 1718.2 + 879
         = 2597.2 步

# 差异
difference = 2643.3 - 2597.2 = 46.1 步
```

**关键发现**：这次被裁剪掉了 **46.1 步**，占运动范围的 2.1%！

#### 物理角度

```python
# original_pos 对应角度
angle_original = (2643.3 - 2048) / 4096 * 360°
               ≈ 52.3°

# safe_pos 对应角度
angle_safe = (2597.2 - 2048) / 4096 * 360°
           ≈ 48.3°

# 角度差异
angle_diff = 52.3° - 48.3° = 4.0°
```

**含义**：腕部被裁剪掉了 **4度** 的移动！

## 🔍 为什么被裁剪？

### max_relative_target = 0.3 的真正含义

在归一化范围 [-100, 100] 下：

```python
max_relative_target = 0.3  # 表示归一化坐标系中的 0.3 个单位
```

**但注意**：这里的 0.3 不是相对于 [-100, 100] 的，而是相对于 **[-1, 1]** 的！

### 实际的裁剪计算

LeRobot 内部首先将 [-100, 100] 转换为 [-1, 1]：

```python
# 归一化到 [-1, 1]
normalized_0_1 = (value + 100) / 200  # 从 [-100, 100] → [0, 1]
normalized_neg1_1 = normalized_0_1 * 2 - 1  # 从 [0, 1] → [-1, 1]
```

**然后应用 max_relative_target**：

```python
relative_target = leader_pos - follower_current_pos  # 在 [-1, 1] 范围

if abs(relative_target) > max_relative_target:
    relative_target = sign(relative_target) * max_relative_target
```

### 为什么 wrist_flex 被裁剪最多？

```python
# original: 60.17 → -1,1范围: (60.17 + 100) / 200 * 2 - 1 = 0.6017
# safe: 55.99 → -1,1范围: (55.99 + 100) / 200 * 2 - 1 = 0.5599

# 差异在 [-1, 1] 范围：0.6017 - 0.5599 = 0.0418
```

**推测当前 Follower 位置**：

假设 Follower 当前在归一化位置 0.3（[-1, 1] 范围），Leader 要求 0.6017：

```python
relative_target = 0.6017 - 0.3 = 0.3017  # 超过 0.3 限制！
safe_target = 0.3  # 被裁剪到 0.3
actual_pos = 0.3 + 0.3 = 0.6  # 只能移动到这里

# 转换回 [-100, 100]：
safe_pos_100 = (0.6 + 1) / 2 * 200 - 100 = 60.0
# 但日志显示 55.99，说明 Follower 当前位置更低
```

## 🎯 关键结论

### 日志中的值是什么单位？

**归一化值 [-100, 100]**：
```python
'original goal_pos': 99.63   # 接近最大值 100
'safe goal_pos': 99.12       # 被稍微裁剪
```

### 裁剪的实际影响

| 关节 | 被裁剪的步数 | 占运动范围 | 角度差异 |
|------|------------|-----------|---------|
| elbow_flex | 6.6 步 | 0.3% | ~0.6° |
| shoulder_lift | 1.1 步 | 0.05% | ~0.1° |
| wrist_flex | 46.1 步 | 2.1% | ~4.0° |

### 为什么 Follower "不动"？

**不是因为被裁剪太多**（实际裁剪很少），而是因为：

1. **Leader 已经在极限位置**（99.63 接近 100）
2. **Follower 当前位置未知**，可能距离很远
3. **每次只能移动 0.3 个单位**（在 [-1, 1] 范围）
4. 如果距离是 2 个单位，需要 **7-8 次循环**才能到达

**30Hz 控制频率下**：
- 7次循环 = 7/30 ≈ 0.23 秒
- 看起来就是"慢慢移动"或"不动"

## 💡 解决方案

### 方案1：确保初始位置接近

让 Follower 和 Leader 的初始位置差距在 **0.5 个单位**（[-1,1]范围）以内，即：

```python
# 在 [-100, 100] 范围内，差距应 < 50
abs(leader_pos - follower_pos) < 50  # 归一化值
```

### 方案2：增大 max_relative_target

```bash
# 从 0.3 增加到 0.8
--robot.left_arm_config.max_relative_target=0.8 \
--robot.right_arm_config.max_relative_target=0.8
```

这样每次可以移动 80% 的运动范围，基本可以一次到位。

### 方案3：使用度数单位（更直观）

```bash
--robot.left_arm_config.use_degrees=true \
--robot.left_arm_config.max_relative_target=30  # 每次最多移动30度
```

## 总结

**日志中的值**：
- 单位：归一化范围 **[-100, 100]**
- 99.63 ≈ 最大运动范围的 99.63%
- -98.22 ≈ 最小运动范围的 98.22%

**裁剪原因**：
- `max_relative_target=0.3` 限制每次移动量（在 [-1,1] 范围）
- 对应 [-100, 100] 范围约 30 个单位
- 如果 Leader 和 Follower 距离大于 30，就会被裁剪

**为什么不动**：
- 不是裁剪太多（实际只裁剪几步）
- 而是初始位置差距太大，需要多次循环才能到达
- 每次移动很小，看起来像"不动"
