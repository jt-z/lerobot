# 数据采集持续报警的根本原因分析

**问题时间**：2026-08-04 14:41
**现象**：即使手动调整了初始位置，数据采集仍持续报警 `Relative goal position magnitude had to be clamped`
**对比**：遥操作脚本 `teleoperate_dual_so101.sh` 运行正常，没有任何报错

---

## 🔍 核心发现：校准文件配置不一致

### 数据采集脚本的配置（有问题）

```bash
# collect_cap_pen_data.sh 第119行
--robot.id=jt_follower_arm \
```

**日志显示实际加载的文件**：
```
'id': 'jt_follower_arm',  # ⚠️ 使用共享的 ID
```

**实际文件路径**（推测）：
```
~/.cache/huggingface/lerobot/calibration/robots/so_follower/
├── jt_follower_arm.json          # ⚠️ 左右臂可能共享这个文件
```

### 遥操作脚本的配置（正常工作）

```bash
# teleoperate_dual_so101.sh 第249行
--robot.id="$FOLLOWER_ID" \
```

其中 `FOLLOWER_ID=jt_follower_arm`

**但实际存在的文件**：
```bash
~/.cache/huggingface/lerobot/calibration/robots/so_follower/
├── jt_follower_arm_left.json     # ✅ 左臂独立校准
├── jt_follower_arm_right.json    # ✅ 右臂独立校准
```

---

## 🎯 问题本质

### 为什么遥操作正常？

**遥操作使用 `lerobot-teleoperate`**：
- 可能内部逻辑会自动查找 `{id}_left.json` 和 `{id}_right.json`
- 或者遥操作模式对初始位置不敏感，直接1:1映射 Leader 到 Follower
- **没有 `max_relative_target` 限制**（遥操作模式下可能禁用了安全限制）

### 为什么数据采集报警？

**数据采集使用 `lerobot-record`**：
- 启用了 `max_relative_target=0.3` 的安全限制
- 尝试从 `jt_follower_arm.json` 加载校准，但实际应该用 `jt_follower_arm_left.json` 和 `jt_follower_arm_right.json`
- **校准文件不匹配导致初始位置计算错误**

## ✅ 解决方案

### 方案1：修改数据采集脚本，使用独立的左右臂 ID（推荐）

编辑 `collect_cap_pen_data.sh`：

```bash
# 删除第119行：
--robot.id=jt_follower_arm \

# 改为左右臂分别指定（在 left_arm_config 和 right_arm_config 里）：
--robot.left_arm_config.id=jt_follower_arm_left \
--robot.right_arm_config.id=jt_follower_arm_right \
```

**完整的修改**：

```bash
# 第115-128行修改为：
RECORD_CMD="lerobot-record \
  --robot.type=bi_so_follower \
  --robot.left_arm_config.port=$LEFT_FOLLOWER_PORT \
  --robot.left_arm_config.id=jt_follower_arm_left \
  --robot.right_arm_config.port=$RIGHT_FOLLOWER_PORT \
  --robot.right_arm_config.id=jt_follower_arm_right \
  --robot.left_arm_config.cameras=\"$LEFT_CAMERAS\" \
  --robot.right_arm_config.cameras=\"$RIGHT_CAMERAS\" \
  --robot.left_arm_config.max_relative_target=0.3 \
  --robot.right_arm_config.max_relative_target=0.3 \
  --teleop.type=bi_so_leader \
  --teleop.left_arm_config.port=$LEFT_LEADER_PORT \
  --teleop.left_arm_config.id=jt_leader_arm_left \
  --teleop.right_arm_config.port=$RIGHT_LEADER_PORT \
  --teleop.right_arm_config.id=jt_leader_arm_right \
  ..."
```

### 方案2：增大 max_relative_target（临时方案）

如果方案1不行，可以临时增大限制：

```bash
# 第122-123行修改为：
--robot.left_arm_config.max_relative_target=1.5 \
--robot.right_arm_config.max_relative_target=1.5 \
```

**注意**：这只是掩盖问题，不解决根本原因。

### 方案3：创建共享的校准文件（不推荐）

如果确实要用共享 ID：

```bash
# 复制 left 的校准文件为共享文件
cp ~/.cache/huggingface/lerobot/calibration/robots/so_follower/jt_follower_arm_left.json \
   ~/.cache/huggingface/lerobot/calibration/robots/so_follower/jt_follower_arm.json

cp ~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/jt_leader_arm_left.json \
   ~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/jt_leader_arm.json
```

**问题**：如果左右臂物理位置不同，共享校准会导致错误。

## 📈 为什么遥操作脚本正常？

查看 `teleoperate_dual_so101.sh` 第154-161行：

```bash
for side in left right; do
    local calib_file="${follower_dir}/${FOLLOWER_ID}_${side}.json"
    if [ -f "$calib_file" ]; then
        print_success "找到 Follower 校准文件: ${FOLLOWER_ID}_${side}.json"
```

**关键**：遥操作脚本的**检查逻辑**期望的是 `jt_follower_arm_left.json` 和 `jt_follower_arm_right.json`。

但在数据采集脚本中，使用的是：
```bash
--robot.id=jt_follower_arm  # 没有 _left 或 _right 后缀
```

**这导致**：
- 数据采集尝试加载 `jt_follower_arm.json`（不存在）
- 或者使用默认值/错误的校准
- 导致归一化计算错误

## 总结

**问题根源**：数据采集脚本使用 `--robot.id=jt_follower_arm`（共享ID），但实际校准文件是 `jt_follower_arm_left.json` 和 `jt_follower_arm_right.json`（独立ID），导致校准文件加载失败或使用错误的校准。

**解决方法**：修改脚本，为左右臂分别指定独立的 ID。

**为什么遥操作正常**：虽然遥操作脚本也用 `--robot.id=jt_follower_arm`，但 `lerobot-teleoperate` 可能没有启用 `max_relative_target` 限制，或者内部逻辑自动处理了 ID 后缀。
