# 稳定配置方案

## 配置对比

### 完整对比表

| 参数 | 原始值 | 稳定值 | 变化 | 原因 |
|------|--------|--------|------|------|
| `optimizer_lr` | 8e-5 | **5e-5** | ↓ 37.5% | 降低学习率，减少参数大幅跳变 |
| `batch_size` | 32 | **16** | ↓ 50% | 减小批次，降低梯度方差 |
| `kl_weight` | 10.0 | **1.0** | ↓ 90% | 🔥 关键修改：大幅降低VAE训练强度 |
| `n_vae_encoder_layers` | 4 | **2** | ↓ 50% | 简化VAE编码器架构 |
| `grad_clip_norm` | 10.0 | **5.0** | ↓ 50% | 更严格的梯度裁剪 |
| `use_vae` | true | **true** | - | 保留VAE能力 |
| `output_dir` | demo_data_dual | **demo_data_dual_stable** | - | 不覆盖原输出 |

### 有效批次大小变化

```
原始配置：batch_size=32 × num_gpus=8 = 256
稳定配置(8卡)：batch_size=16 × num_gpus=8 = 128
稳定配置(7卡)：batch_size=16 × num_gpus=7 = 112
```

## 参数选择原理

### kl_weight: 10.0 → 1.0

**VAE损失的作用**：
```
总损失 = 重建损失(L1) + kl_weight × KL散度
```

**权衡**：
- `kl_weight` 太小：VAE退化为普通自编码器，失去正则化作用
- `kl_weight` 太大：KL散度主导训练，导致数值不稳定

**选择1.0的原因**：
- ACT论文中常用值为 1.0 或更小
- 让重建损失和KL散度处于同等重要性
- 10.0是某些实现的默认值，但对于机器人任务过于激进

**预期效果**：
- VAE仍能学习有意义的潜在表示
- 避免 `log_sigma_x2_hat` 剧烈变化
- 数值稳定性大幅提升

---

### batch_size: 32 → 16

**大批次的问题**：
1. 梯度估计方差大（尤其当数据有异常样本时）
2. 内存占用高，可能导致数值精度问题
3. 单个异常样本的影响被放大256倍（原有效批次）

**小批次的优势**：
1. 更频繁的参数更新
2. 每步的异常影响更小
3. 训练过程更稳定（虽然可能收敛稍慢）

**为什么选16**：
- 有效批次 16×8=128 仍然足够大
- 平衡了稳定性和训练效率
- 符合ACT的常用设置

---

### optimizer_lr: 8e-5 → 5e-5

**学习率与VAE稳定性的关系**：
```
参数更新 = 参数 - lr × 梯度
```

**更小学习率的作用**：
1. 单步参数变化更小
2. 减少跳入数值危险区域的概率
3. 给网络更多"探索"时间找到稳定的参数配置

**为什么是5e-5**：
- 相对于8e-5降低了37.5%
- 仍在ACT推荐范围内（1e-5 到 1e-4）
- 配合其他改进，形成综合稳定效果

---

### n_vae_encoder_layers: 4 → 2

**VAE编码器的作用**：
```
图像 → CNN backbone → VAE encoder → 潜在分布(μ, σ²)
```

**层数的影响**：
- **4层**：表示能力强，但参数多，训练难度大
- **2层**：足够提取特征，同时保持稳定性

**为什么减少层数有效**：
1. 减少非线性变换的累积
2. 降低 `log_sigma_x2_hat` 的动态范围
3. 更容易收敛到稳定状态

**权衡**：
- 可能略微降低VAE的表达能力
- 但对于双臂机器人任务，2层编码器通常足够

---

### grad_clip_norm: 10.0 → 5.0

**梯度裁剪的工作原理**：
```python
if grad_norm > grad_clip_norm:
    grad = grad * (grad_clip_norm / grad_norm)
```

**更严格裁剪的好处**：
1. 即使产生异常梯度，也会被更早截断
2. 防止单个batch的极端梯度破坏训练
3. 增加训练鲁棒性

**为什么是5.0**：
- 原来10.0仍允许较大的梯度
- 5.0更保守，适合VAE训练
- 配合更小学习率，双重保护

## 预期训练效果

### 模型参数变化

```
原始配置：num_learnable_params=51,611,532 (52M)
稳定配置：num_learnable_params=42,945,164 (43M)
```

**参数减少原因**：
- VAE encoder从4层降至2层
- 减少了约8.7M参数（17%）

**影响**：
- 模型略微简化，但核心能力保留
- 训练更快，内存占用更低

---

### 训练速度预估

| 指标 | 原始配置 | 稳定配置(8卡) | 稳定配置(7卡) |
|------|---------|--------------|--------------|
| 有效批次 | 256 | 128 | 112 |
| 每轮迭代数 | 29220/256=114 | 29220/128=228 | 29220/112=261 |
| 到达37500步时间 | 基准 | ~2倍 | ~2.3倍 |
| 单步速度 | 基准 | ~1.1倍快 | ~1.1倍快 |
| **预估总时长** | **T** | **~1.8T** | **~2.1T** |

**说明**：
- 虽然迭代数增加，但单步更快（批次小+参数少）
- 最终收敛可能更好（小批次有正则化效果）

---

### 收敛质量预期

**优势**：
- 更稳定的训练曲线
- 避免NaN崩溃
- 小批次有隐式正则化效果

**可能的代价**：
- VAE表达能力略微下降
- 可能需要稍多的steps达到相同性能

**整体评估**：
稳定性收益远大于轻微的性能损失

## 启动脚本

### 8卡版本（start_train_act_stable.sh）

```bash
#!/bin/bash
cd /home/ksa/lerobot/self_scripts/

echo "使用稳定配置开始训练（降低KL权重、减小batch size、更保守的学习率）"
accelerate launch --multi_gpu --num_processes=8 $(which lerobot-train) \
    --config_path=train_config_act_stable.json
```

### 7卡版本（start_train_act_stable_7gpu.sh）⭐

```bash
#!/bin/bash
cd /home/ksa/lerobot/self_scripts/

echo "使用稳定配置开始训练（7张GPU，降低KL权重、减小batch size）"
CUDA_VISIBLE_DEVICES=1,2,3,4,5,6,7 accelerate launch --multi_gpu --num_processes=7 $(which lerobot-train) \
    --config_path=train_config_act_stable.json
```

**关键差异**：
- 使用 `CUDA_VISIBLE_DEVICES` 排除GPU 0
- `--num_processes=7` 对应7张可用GPU

## 如果还是失败怎么办

### 方案B：完全禁用VAE

**配置**（train_config_act_no_vae.json）：
```json
{
  "policy": {
    "type": "act",
    "optimizer_lr": 1e-4,
    "use_vae": false
  },
  "batch_size": 32
}
```

**权衡**：
- ✓ 彻底消除VAE数值问题
- ✓ 训练更稳定
- ✗ 失去VAE的泛化能力
- ✗ 可能在未见过的场景表现下降

```
训练崩溃

    │

```

## 最佳实践建议

### 1. 总是从保守配置开始

首次训练新数据集时：
- 使用较小的 `kl_weight` (1.0)
- 使用中等批次大小 (16-32)
- 使用保守学习率 (5e-5)

### 2. 监控关键指标

训练时关注：
- 梯度范数是否稳定（不应该突然跳变）
- KL散度损失是否在合理范围（0.1-10.0）
- L1损失是否平稳下降

### 3. 渐进式调优

如果训练稳定：
- 可以逐步增大 `kl_weight`
- 可以增大批次大小
- 可以提高学习率

但**每次只调整一个参数**，观察效果

### 4. 保留checkpoint

每2000步保存checkpoint（已配置），以便：
- 从最后的稳定点恢复
- 对比不同配置的效果
- 避免从头开始重新训练
