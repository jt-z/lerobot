## 问题记录

### 问题1：NaN梯度导致训练崩溃

**表现**：
```
step:200 ... loss:4.985 grdn:nan
RuntimeError: CUDA error: unspecified launch failure
```

**排查过程**：
1. 检查日志发现梯度范数为NaN
2. 分析代码 `modeling_act.py:148-162`
3. 定位到VAE的KL散度计算：
   ```python
   mean_kld = (-0.5 * (1 + log_sigma_x2_hat - mu_hat.pow(2) - (log_sigma_x2_hat).exp()))
   ```
4. 识别出 `exp(log_sigma_x2_hat)` 可能产生无穷大

**根因**：
- `kl_weight=10.0` 使VAE损失主导训练
- VAE编码器4层过于复杂
- 大批次(256)导致梯度估计方差大
- 当 `log_sigma_x2_hat` 变大时，`exp()` 爆炸 → inf → NaN

**最终方案**：
- 降低 `kl_weight` 至 1.0
- 减小批次至 16 (有效批次=128)
- 降低学习率至 5e-5
- 简化VAE为2层
- 更严格的梯度裁剪(5.0)

---

### 问题2：训练卡住，GPU/CPU利用率低

**表现**：
- DDP警告后无进度日志
- CPU利用率12.6%
- 多个 `pt_data_worker` 进程但效率低

**排查过程**：
1. 观察 `top` 和 `nvitop` 输出
2. 发现开启了 `CUDA_LAUNCH_BLOCKING=1` 和 `TORCH_USE_CUDA_DSA=1`

**根因**：
调试模式环境变量让CUDA操作变成同步执行，严重影响性能

**解决方案**：
创建非调试版训练脚本 (`start_train_act_stable.sh`)

---

### 问题3：GPU 0硬件失效

**表现**：
```
Unable to determine the device handle for GPU0: 0000:55:00.0: Unknown Error
CUDA initialization: CUDA unknown error
Device 'cuda' is not available. Switching to 'cpu'.
```

**排查过程**：
1. 运行 `nvidia-smi` 发现只列出GPU 1-7
2. 确认GPU 0 (PCI 0000:55:00.0) 完全不可见

**根因**：
- 之前的CUDA kernel崩溃可能导致GPU进入异常状态
- 或硬件问题（供电、散热、PCIe连接）

**应对方案**：
- 短期：使用 `CUDA_VISIBLE_DEVICES=1,2,3,4,5,6,7` 排除GPU 0
- 长期：需要重启服务器或检查硬件

## 关键决策

### 决策1：选择稳定配置而非禁用VAE

**选项**：
- A. 降低VAE参数（kl_weight, 层数）
- B. 完全禁用VAE (`use_vae=false`)

**选择**：A

**原因**：
- VAE能提高ACT的泛化能力
- 问题出在配置过激进，而非VAE本身
- 降低kl_weight至1.0可保留VAE优势同时避免数值问题

---

### 决策2：7卡训练而非等待GPU修复

**选项**：
- A. 重启服务器修复GPU 0
- B. 直接用7卡训练

**选择**：B

**原因**：
- 有效批次从128变为112，影响不大
- 避免等待时间，可立即继续训练
- GPU 0可能需要硬件检查，修复时间不确定

---

### 决策3：梯度裁剪从10.0降至5.0

**原因**：
- 原配置10.0仍允许较大梯度
- 结合其他稳定性改进，5.0更保守
- 与更低的学习率配合效果更好
